# 화면 최대·최소 배율 정하기 (프롬프트)

isometric-rpg 리포에서 **지금 게임 그래픽 기준으로 가장 알맞은 화면 확대 한계(최대 배율)와 축소 한계(최소 배율)**를 측정으로
정하고, 코드에 반영해 줘. 캐릭터 스프라이트 재베이크, 게임 규칙·AI·유닛 활성 범위 같은 시뮬레이션 값은 바꾸지 마.

## 전제

- 화면은 게임 픽셀 캔버스(w × h)를 정수배(`devScale`)로 키워 보여준다. PC 기본은 세로 360 게임 픽셀(`PC_BASE_H`),
  터치는 화면 높이의 58%를 240~450 사이로. 줌 `z`는 "기본보다 몇 배 가깝게"이고, 보이는 세로 게임 픽셀(이하 **rows**)
  ≈ 기본 높이 ÷ z. 확대·축소 버튼은 정수 배율을 한 단계씩 바꾼다.
- 한계는 **줌 값이 아니라 rows(그리고 필요하면 게임 픽셀 너비)로** 정한다. 화면에서 보이는 것은 rows가 결정하고,
  같은 rows면 1080p든 4K든 같은 그림이기 때문이다. 결과를 줌 값(`ZOOM_MIN` / `ZOOM_MAX`)이나 rows 한계로 코드에 넣는다.

## 기준 — 축소 한계(rows 최대)

1. **팝인 없음 (필수).** 유닛은 플레이어 주변 `|dx|, |dy| < 34` 상자(`game.js` activeUnits) 안에서만 그려진다. 화면이 이
   상자보다 크면 유닛이 화면 안에서 갑자기 나타나거나 사라진다. 게임에서 실제로 걸으며(허브 위층·언더시티·크리스토프시스)
   **보이는 영역(하단 콘솔 위) 안에서 생기거나 없어지는 유닛 스프라이트 수를 rows별로 센다.** 0이어야 한다.
   카메라가 맵 가장자리에서 멈춰 플레이어가 화면 가운데에서 벗어나는 경우도 포함한다. 화면비(16:9, 16:10, 21:9)마다 따로 본다.
2. **성능.** rows가 커질수록 그릴 게임 픽셀이 늘어난다. 같은 장소에서 `renderer.render` + `post.render` 프레임 시간
   중앙값을 rows별로 재고, 기본(360) 대비 **2배를 넘지 않을 것.**
3. **가독성.** 1080p에서 캐릭터(약 52 게임 px) 키가 **80 css px 이상**이고, 이름표·체력 막대가 겹치지 않을 것.
4. 맵 밖(난간 너머 배경)이 화면을 얼마나 차지하는지도 rows별로 기록한다(참고 값).

## 기준 — 확대 한계(rows 최소)

1. **전술 시야 (필수).** 플레이어를 쏠 수 있는 적은 화면에 보여야 한다. 가장 긴 적 사거리(B1 = 7 타일)에 선 적이
   8방향 모두에서 **발과 몸 가운데까지 보이는 영역(하단 콘솔 위) 안에** 들어올 것. 카메라 위치(PC: 보이는 높이의 55%,
   터치: 60%)와 콘솔 높이(css px 고정)를 넣어 계산하고, 실제로 적을 그 거리에 세워 스크린샷으로 확인한다.
   참고로 적이 알아채는 거리(10 타일)가 다 보이는지도 기록한다.
2. **픽셀 블록 크기.** 게임 픽셀 하나가 화면 높이의 1/rows다. 이 게임은 굵은 도트가 아니라 프리렌더 3D 스프라이트라서
   너무 키우면 계단·뭉개짐이 두드러진다. 지금까지 실제 기기에서 맞춰 본 가장 가까운 보기(폰 기본 240 rows)보다
   **가깝게 가지 않는다.**
3. 확대한 화면에서 스프라이트·이펙트·지형이 깨지거나 어색하지 않은지 스크린샷으로 확인한다.

## 진행

1. 측정 스크립트(`tools/qa/zoomlimits.mjs`)를 만든다. rows를 바꿔 가며(예: 180~900) 1920×1080 화면을 흉내 내어
   (`computeDevScale`을 바꿔 끼워 임의 rows로) 위 수치를 모두 뽑는다. 팝인은 여러 경로를 실제로 걸으며 센다.
2. 기준을 모두 만족하는 rows 범위 [rows_min, rows_max]를 정한다. 화면비에 따라 달라지면 너비 한계도 같이 둔다.
3. 코드에 반영한다(`renderer.js` 줌 한계, `zoom.js` 단계). 정수 단계 때문에 화면마다 실제로 갈 수 있는 배율 목록을
   표로 만든다: 1366×768, 1536×864(1080p 125%), 1920×1080, 2560×1080, 2560×1440, 3840×2160, 폰(S25 Ultra 가로).
   **모든 화면에서 기본 배율이 범위 안에 있고, 확대·축소가 적어도 한 단계씩은 될 것.** 안 되는 화면은 이유를 적는다.
4. 반영한 뒤 다시 플레이로 확인한다: 최소·최대 배율에서 걷기·전투 스크린샷(여러 프레임), 팝인 수, 클릭 정확도.
   `tools/qa/smoke.mjs`, `tools/qa/resolution.mjs` 통과.
5. README·`docs/GAME_DESIGN.md` 2.1.1의 수치를 고치고, 브랜치에 커밋·푸시한다.

## 보고

- rows별 측정표(팝인 수, 프레임 시간 비율, 캐릭터 css px, 맵 밖 비율, 사거리 7 적이 보이는지).
- 정한 범위와 이유(어느 기준이 한계를 정했는지), 화면별 배율 단계 표, 최소·최대 배율 스크린샷.
