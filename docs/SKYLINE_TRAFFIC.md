# 코러산트 하늘 교통 (에어스피더)

코러산트의 차선(`world.traffic`)을 따라 흐르던 **빛줄기를 에어스피더 스프라이트로 바꾼** 시스템과, 먼 도시 위를 지나는
배경 교통. 스프라이트는 첨부한 8방향 차량 시트 두 장(`reference/unsorted/image_3.png`, `image_4.png`)에서만 잘라 쓴다
(예전 `CATEGORY 4` 시트는 전면 교체로 더 쓰지 않는다).

> 요청은 Unity C#(`CoruscantSkylineTraffic.cs`, `TrafficVehicleController.cs`) 형식이었지만 이 게임은 브라우저용
> Vite + JavaScript라서, 같은 구조를 게임 코드로 구현했다: 매니저 = `SkylineTraffic` / `LaneTraffic`
> (`src/gfx/skylineTraffic.js`), 차량 = 풀의 객체.

## 스프라이트

- 기체 8종 × 8방향(시트의 열 = 기수 방향 S, SW, W, NW, N, NE, E, SE): 빨간 로드스터, 에어택시, 화물 운반선, 레이서 07,
  검은 인터셉터, 클래식 로드스터, 컨테이너 화물선, 파란 레이서. 차급: swoop(레이서) · cruiser · commuter(택시) · cargo.
- `tools/sprites/traffic/extract.py`: 시트의 평평한 회색 배경과 기체 밑 부드러운 바닥 그림자(윤곽에서 닿는 어둡고 평평한
  무채색 픽셀)를 잘라 내고, 시트의 밝은 테두리 번짐을 몇 겹 벗긴 뒤, 외곽선을 회색과의 거리로 매팅한다. 그다음 게임 크기로
  **한 번만** 줄인다(`SCALE = 0.5`, 프리멀티플라이드 Lanczos) → `public/sprites/traffic/traffic.png`, 반 크기
  `traffic_half.png`(먼 배경용, 짝수 좌표 정렬이라 정확히 대응), `traffic.json`(기체마다 차급, 방향마다 위치·크기·뒤쪽 점).
- 게임은 픽셀을 그대로 그린다: 실행 중 크기 변경·색 덧칠·빛 그리기 없음(엔진 불빛은 시트에 그려진 것).

## 구성

| 깊이 | 구현 | 어디에 그리나 |
|---|---|---|
| 차선 교통 | `LaneTraffic` | 월드의 모든 차선을 **플랫폼 가장자리 바로 아래 높이**로 내려, 소품·유닛과 함께 깊이 정렬(뒤의 플랫폼·외벽 앞, 앞에 선 것 뒤) |
| 먼 배경 | `SkylineTraffic` | 배경(`cityBackdrop.js`)의 가운데 탑 층과 가장 가까운 탑 층 사이, 지형보다 먼저, 반 크기 |

차선은 **걸을 수 있는 땅 위를 지나지 않는다.** 이 시점에서는 높이 떠 있는 기체도 그 아래 바닥에 서 있는 것처럼 보이기 때문에
(언더시티 거리 위·플라자 위를 지나던 기체가 그렇게 보였다), 차선이 바닥(VOID가 아닌 칸)을 지나면 가장 가까운 빈 하늘 쪽으로
옆으로 옮기고, 나란한 차선과 1.5칸 이상 띄운다. 그럴 자리가 없는 차선은 비워 둔다(현재 17개 중 2개). 그래서 예전에 언더시티
거리 위를 지나던 빛줄기 차선은 거리 대신 둘레의 낭떠러지로 옮겨졌다.

## 움직임

- **직선**: 차선은 등각 축(월드 x 또는 y) 위의 직선이고, 화면 위치는 차선 시작점에서 정수 픽셀 2:1 계단(한 줄에 옆으로
  2픽셀)으로 정해져 떨림·지그재그가 없다. 곡선·흔들림·위아래 출렁임 없음.
- **방향과 스프라이트**: 차선은 원래 방향 그대로 흐르고, 화면에서 가는 방향에 기수가 맞는 뷰를 쓴다(+x 오른쪽 아래 SE,
  −x 왼쪽 위 NW, +y 왼쪽 아래 SW, −y 오른쪽 위 NE). 먼 배경도 네 대각선 중 하나로 가며 같은 규칙.
- **허공에서 튀어나오지 않음**: 차선을 레벨 양 끝 너머로 30칸씩 늘려 항상 화면 밖에서 들어와 화면 밖으로 나간다
  (풀 260대가 모든 차선을 채울 만큼). 먼 배경은 화면 한쪽 밖에서 반대쪽 밖까지 가로지른다.
- **속도**: 차급마다(레이서 1.35 > 크루저 1.12 > 택시 1 > 화물 0.68, 차선 속도에 곱함), 차마다 ±10%. 앞차가 느리면
  따라 줄이고 4.5칸 안으로 붙지 않는다.
- **스폰**: 지수분포 간격(박자 없음), 직전 차가 입구를 비운 뒤에만. 레벨을 열 때 이미 흐르도록 미리 채운다.

## 직접 플레이 검사

`node tools/qa/trafficplay.mjs <out_dir> [spot] [seconds]` — 게임을 1/60초씩 진행하며 모든 차의 그려진 위치를 기록하고
(카메라 이동은 뺌) **화면 안에서 갑자기 나타난 차**, **진행 방향이 뒤집힌 걸음(지그재그)**, **멈췄다 튀는 차**,
**스프라이트 기수와 실제 진행 방향이 다른 차**를 센다. 6프레임마다 화면을 저장해 눈으로도 본다. 기준: 모두 0.
장소: `corner_nw`, `terrace`, `pad`, `lift`, `plaza`, `corner_se`, `west_alley`.

## 설정 방법 (엔진 설정 대응)

| Unity라면 | 여기서는 |
|---|---|
| Sorting Layer / Order | 차선: `renderer.js`의 깊이 정렬 목록(`put(…, car)`); 먼 배경: `cityBackdrop.js`의 탑 층 루프(`TIERS[0].after`) |
| 프리팹 · 스프라이트 풀 | `public/sprites/traffic/*` ← `python3 tools/sprites/traffic/extract.py`(`--contact out.png`로 전체 확인표) |
| 기체 · 차급 | `extract.py`의 `CRAFT`((시트, 행) → 이름, 차급), 크기 `SCALE` |
| 파라미터 | `skylineTraffic.js`: `CLASSES`(속도 배수, 빈도), `TIERS`(먼 배경: 시차, 풀, 스폰률, 높이 띠, 속도), `EXT`·`POOL`·`LEN` |
| 차선 경로 | `src/world/worldgen.js`의 `this.traffic`(x0, y0 → x1, y1, 높이 z, 속도, 평균 간격) |
